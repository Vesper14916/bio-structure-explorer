## Interface notes for S3 (ST6), S4 (ST7), S5 (ST9), U1, R3
- Events carry semantics, not geometry, and every event has `data.target` (`'rnap'`, `'sigma'`, `'ribosome'`, `'small'`, `'large'`, a factor id, or `'trna:<slot>'`). Use the helpers (O(log E), no allocation) rather than scanning events.
- `stateAt` fills `t`, `chapter`, `chapterProgress`, `caption`, `counters`, `highlight`, `shot`, and resets every other field to the defaults of `createWorldState()` on each call. It truncates `machines`, `trnas` and `fx` to length 0, so contributors must write those arrays fully on every call; to keep the no-allocation rule, pool entries on `out` itself (for example a non-enumerable property), not in module state.
- `shot.from` is the previous segment's shot, including across chapter boundaries (the first segment of each chapter records the previous chapter's last shot); null only at the start of the story. `shot.blend` ramps over 1.2 s; R3 may compute its own duration from camera travel.
- `buildStory(..., { timeline })` builds a story from a prebuilt timeline such as `tests/fixtures/story-mini.json`.
- Coupled mode uses D = 48 until task A4 records `source.coupling.D` on `rnap-ec`; `meta.dSource` says so. `buildTimeline` throws for D outside 38…139 (outside that range the coupled chapter formulas of §6.4 do not fit the construct).
