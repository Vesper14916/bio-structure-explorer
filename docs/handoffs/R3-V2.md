# Handoff — R3-V2 (Visual evidence sweep)

Branch: `claude/project-thread-weimhy` (committed by the lead). Scope: `tools/evidence/sweep.mjs`, `docs/evidence/r3/sweep/`, this file. No other file was edited. `npm test` and `npm run smoke` were not run (CPU-sensitive timing test, per the brief).

## Changed files

- `tools/evidence/sweep.mjs` (new): rerunnable capture script. Usage: `node tools/evidence/sweep.mjs [--mode sequential|coupled] [--chapters 1-16] [--dsf 1|2] [--devices desktop,iphone13] [--shots start,mid,end] [--out dir]` (`--devices` and `--shots` were added by the lead to allow a quick desktop-only run). Serves the repo root on a loopback port, opens `index.html?mode=express&scene=v2&chapter=1&frac=0.5&paused=1&quality=medium`, waits for `window.helix.storyScene` (180 s), and for each chapter and each fraction (start 0.02, mid 0.5, end 0.98) calls `setChapter(index, {frac, instantCamera:true})`, waits five requestAnimationFrame pairs, reads `state()` (chapterIndex, t, caption) and takes a JPEG at quality 78. Camera option is left at `Auto`. Desktop is 1280x800; phone is `devices['iPhone 13']` with `deviceScaleFactor` 1 by default. Each device has its own browser launch, run one after another. Contact sheets are rendered from a local HTML grid with data URLs, in the same browser type. Console and page errors are collected per device; the script exits 1 if there are any. `--mode coupled` calls `setMode('coupled')` and stops at chapter 5 (chapters 6-12 are logged as skipped, blocked on R3-S5 / ST9).
- `docs/evidence/r3/sweep/sequential/desktop/` (48 JPEG) and `sequential/iphone13/` (48 JPEG): all 16 sequential chapters, start/mid/end, each with `manifest.json`.
- `docs/evidence/r3/sweep/coupled/desktop/` (15 JPEG) and `coupled/iphone13/` (15 JPEG): coupled chapters 1-5 only (smoke check, run once).
- `docs/evidence/r3/sweep/sequential-desktop-contact.jpg`, `sequential-iphone13-contact.jpg`, `coupled-desktop-contact.jpg`, `coupled-iphone13-contact.jpg`: contact sheets (rows = chapters, columns = start/mid/end, cell label `NN id`).
- `docs/evidence/r3/sweep/index.md`: generated by the script from the manifests. Lists every shot with chapter, id, shot name, story time t, whether the state matched, file and on-screen caption.
- `docs/handoffs/R3-V2.md` (this file).

Total: 126 shots and 4 contact sheets (130 JPEG), about 16 MB on disk.

### Deviations (deliberate)

- **dsf 1 by default** (PLAN §9.2 rule 6 asks for 2x). A 2x software-GL capture takes about 45 s. Use `--dsf 2 --out <other dir>` for a 2x run; it was not run.
- **Five rAF pairs** is the wait the brief asked for. At software GL, a desktop shot took 35-140 s and a phone shot 15-85 s (the slowest runs were while the machine was busy).

### Incident during the run

The first full sequential run stopped when its Chromium closed during `ch02 end` (desktop, `page.screenshot`: "Target page, context or browser has been closed"). The cause was not diagnosed. The script was changed so that each device has its own browser launch, and a closed page now stops that device with a recorded failure instead of repeating errors. The full run was then repeated from chapter 1 and completed with 0 failures. The output files from the repeated run are the ones in this folder.

## Design gaps

- **Camera inside crowd** (04, 06, 14 and most of 02-05): the default `Auto` framing places the camera in the crowd in several chapters, so the subject is occluded. Recommend a crowd-aware framing rule or a cutaway check for these chapters.
- **Empty start frames** (08 start, 10 start, 07 end): the subject is off-frame. Recommend a rail target that always includes the active molecule.
- **Labels under the header card**: several top labels (04, 08, 14) are hidden behind the brand card on desktop.
- **Panel covers the right third on desktop, and the lower half on phone**: this is the existing layout and was not changed; the subject is not covered in the shots read.
