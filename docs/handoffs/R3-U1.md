## Design gaps

All CSS outside the exact `PLAN.md` §4.8 block was intentionally left untouched per the closed design system rule. The following three layout/CSS gaps were observed visually and should be decided by the Chief before or during ST9/ST10 polish:

1. **`Story` segmented pill width (`Step by step` / `Coupled`) inside `div.group.row-between`:**
   - Visible in `desktop-ch1.jpg`, `desktop-ch6.jpg`, `phone-ch1-expanded.jpg`, and `phone-ch6.jpg`.
   - With `Story` (`Step by step` / `Coupled`) and `Speed` (`0.5×` / `1×` / `2×` / `4×`) sharing equal `.grow` columns inside the 384 px desktop panel (and 390 px phone width), the `"Step by step"` text slightly overflows the right edge of its 50% `.seg-thumb` indicator by ~6–10 px.
   - Suggested Chief decision: either give `Story` and `Speed` their own stacked `div.group` rows (or weight `Story` slightly wider via flex-grow / tighten `.seg-sm .seg-btn` horizontal padding or copy to `"Stepwise"` if copy edits are permitted).
2. **`ol` list reset and `.chapter-row` full-width button inside `<li>`:**
   - `css/style.css` line 57 resets `:where(.ui-root ul) { list-style: none; }` but does not include `ol`, and the §4.8 `.chapter-row` rule does not set `width: 100%`.
   - Workaround in `js/ui/view-story.js`: set inline `style: { listStyle: 'none' }` on each `<li>` and `style: { width: '100%' }` on each `.chapter-row` button so `ol.chapter-list` renders without duplicate decimal markers or shrunk rows.
   - Suggested Chief decision: if CSS edits outside §4.8 are later opened, add `ol` to the reset selector and `width: 100%` to `.chapter-row`, then remove the two inline style properties from `js/ui/view-story.js`.
3. **Mobile peek height (`PEEK_H = 112`) caption line clipping:**
   - Visible in `phone-ch1.jpg`.
   - With `--peek-h` and mobile rules unchanged per brief, the collapsed peek sheet fits the play/restart/scrub bar, the chapter pill + `1 / 16` counter, and the first line of the chapter caption; lines 2–3 of the caption sit below the peek fold until the user expands the sheet (`phone-ch1-expanded.jpg`). This matches Round 1's peek behavior and preserves 3D canvas space, but is noted here in case the Chief wants a 2-line clamp or slightly taller peek for Express v2.
